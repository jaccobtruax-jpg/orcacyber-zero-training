What it is

OrcaCyber Zero 1.5 (model id orca/orcacyber-zero-1.5, by Orca, released 2026-10-10) is the successor to OrcaCyber Zero 1.0: a frontier cybersecurity model post-trained for security research and authorized security engineering. It is built for complex, multi-step security workflows — long-context reasoning, native function calling, structured outputs.

  • Focused on P0/P1s and zero-days — deliberately tuned for the findings that demand action, not a general-purpose code model.
  • Optimized to minimize false positives — the core differentiator. Less of a team's time goes to findings that aren't real.
  • Runs on the OrcaCyber harness — the agentic security harness that powers CyberGym evals.
  • Offensive and defensive capable — one model for red teams and blue teams, which is exactly why access is gated.
Positioning in one line: "The model that finds real P0/P1s and zero-days — and doesn't cry wolf."

One model for red teams and blue teams

Red team

  • Vulnerability research & reproduction — find the flaw, then reproduce it against a target you're authorized to test.
  • Exploit development — build a proof of concept that shows the impact of a confirmed vulnerability in the report.
  • Penetration testing — drive recon, enumeration and validation across an authorized engagement, step by step.

Blue team

  • Triage without the noise — review reported issues with a model built to minimize false positives; focus on the P0s and P1s.
  • Security auditing — audit code and get findings back in a structured form.
  • Patch verification — reproduce a bug, apply the fix, and re-test it.

Drops into the stack you already run

An OpenAI-compatible API: point the SDKs, scanners, agent frameworks and CI jobs at OrcaRouter and set the model name.

  • OpenAI-compatible API — use the SDK/client you already have; just change base URL and model.
  • Native function calling — hand it scanners, sandboxes and ticketing as tools and let it call them.
  • Structured JSON output — findings come back as structured output your pipeline can parse.
  • Agents and harnesses — use it as the reasoning model inside your agent framework or security harness.

Access is gated — this is a feature, not a hurdle

Both OrcaCyber models are offensive-capable, so access requires business verification, access is logged, and all use is bound by the Acceptable Use Policy (authorized work only). Until a workspace holds the Security Research tier, calls to a Cyber model return 403.

The verification ladder

RungWhat it provesUnlocks
1 · Payment method on fileAccount is chargeable; identifies nobodyNo models on its own
2 · Identity verifiedGov ID check bound to a real personRequired, not enough
3 · Business verifiedRegistered company, proven claim to its domain, clean sanctions screenUnlocks the cyber models
4 · Contracted researcherNamed researchers, signed authorized-scope statement, contractCaps negotiated at this rung

The unlock flow (orcarouter.ai/research)

  1. Work email — must be at the org's own domain; public mailboxes rejected.
  2. Passkey — each person who calls needs their own.
  3. Card — workspace admin adds one in Billing; $0 check, never charged, prepaid cards rejected.
  4. Policy + request — accept the Security AUP and request access (any member above Viewer can send it).
  5. Review — approved on the spot, or a reviewer answers within a few business days; decision emailed.

Some workspaces are asked for more — an ID check, a DNS record for the company domain, an engagement, or the offensive-capability terms (owner-only to accept).

Engagements: offensive work (payload, implant, exploit development) is permitted only inside a live, authorized engagement — client, authorized scope, end date, your reference. The customer must be able to produce the client's written authorization on request. This is the AUP boundary; do not coach around it.

Who it's for: penetration testers and red teams under client authorization, security vendors and in-house security teams, and researchers studying vulnerabilities, malware or detection. The tier is granted to a workspace, not a person or key — every key in an approved workspace can call Cyber models. Contracted-researcher rung: providers@orcarouter.ai.

Objection handling

"Is it safe to let an AI do offensive work?"

Access is the answer: business verification, an Acceptable Use Policy that permits authorized work only, logged access, and offensive-capable work confined to live, authorized engagements. That's the governance layer general-purpose models don't have.

"Why not just use GPT/Claude/a general model?"

General models aren't post-trained for security workflows, aren't tuned to suppress false positives, and won't reliably drive scanner/sandbox tooling. Zero is: Cybench 100.0 on unrestricted agent runs, CyberGym 98%+ on the OrcaCyber harness, native function calling, structured findings, 1M-token context.

"How do I know findings are real?"

That's the design goal — minimal false positives, P0/P1 focus, and structured output your pipeline can verify. Fewer bogus findings means less triage time spent on noise.

"Context / repo too big?"

1M-token context on both models; point them at OrcaCyber Ultra for whole-repository scanning in one pass.

"What does it cost?"

$3.00/M input, $7.50/M output (same input price as Zero 1.0). Cache reads at $0.75/M. Zero Data Retention available for sensitive workloads.

"How fast can we get access?"

Verification starts at orcarouter.ai/research — work email, passkey, card, AUP, request. Often approved on the spot; worst case a reviewer answers in a few business days. Bigger enterprises wanting negotiated caps go through the contracted-researcher rung (providers@orcarouter.ai).

Demo flow (10 minutes)

  1. Open with the problem: "How much of your team's week goes to false positives?"
  2. Show the model id (orca/orcacyber-zero-1.5) in the catalog and the 1M context.
  3. Run the quickstart — point the OpenAI SDK at https://api.orcarouter.ai/v1 and audit a small auth codebase for "P0/P1 issues."
  4. Show the structured finding — severity, reproduction, patch verification loop.
  5. Hand it a tool (function call to a scanner) to demonstrate native tool use.
  6. Close on access: "You're business-verified — start at orcarouter.ai/research, usually same-day."
Demo caution: only demo against code the customer owns or has written authorization to test. Never demo offensive work without a live, authorized engagement in place.
